## 3. Agent-earns / web3 (x402)

The sharpest edge: the agent itself earns. Using the [x402 protocol](https://github.com/coinbase/x402), an agent requests a resource, the server answers HTTP `402 Payment Required` with payment terms, the agent pays on-chain in stablecoin, the server returns the resource. No accounts, no API keys, no invoicing — payment is a property of the request. This enables cents-to-dollars-per-call pricing that is operationally impossible on card rails.

## How this index stays current

This is a living index, not a static list. The network's **`market-researcher` agent reads it at the start of every run and writes findings back at the end** — so each run starts smarter than the last. It runs on a cadence (the freshness loop, defined in the [`income-market-intel`](https://github.com/frankxai/agentic-income-skills/blob/main/skills/income-market-intel/SKILL.md) skill):

1. **Re-verify the catalog** — do the joined programs still pay what they claimed? Flag rate changes, closed programs, new recurring options.
2. **Re-scan the market** — what rose, what saturated, what changed platform rules. Update each entry's `lastVerified`.
3. **Flag decay** — surface models whose underlying tool lost its program, dropped its rate, or got out-competed.
4. **Surface, don't auto-act** — the loop reports; the operator acts. Never auto-publish, auto-spend, or auto-send.

Boredom is the point: research → verify → route → review → repeat. That loop is the difference between an index that earns for years and a directory that rots.

**This is the one canonical income index.** Do not spawn parallel income lists (no `awesome-income-agent-skills`). Income models consolidate here.
